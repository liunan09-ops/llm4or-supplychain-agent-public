# 简历表述：只写已掌握和能复现的部分

项目名称可用：**面向供应链补货的 LLM 决策 Agent**。

技术栈：Python、FastAPI、Pydantic、LLM JSON Output、SciPy/HiGHS、MILP、SQLite、Pytest。

下面是候选表述，不是已经获得的个人能力认证。确认自己能解释并独立修改对应模块后再使用；不得把 AI 辅助搭建说成全部独立原创。

- 面向单仓单期补货场景，实现“自然语言参数解析—MILP 求解—独立可行性验证—结果解释”的受控 Agent 工作流，处理预算、MOQ、供货上限、交期及服务水平约束。
- 接入真实大模型 JSON 输出与严格参数校验，明确区分优化、澄清和拒绝请求；实现模型故障处理、工具执行记录和本地审计，不允许模型直接执行采购。
- 构建固定的中文业务回归集，分别评估请求分类、完整参数匹配、错误执行、方案可行性及调用耗时；实际用例数与指标引用最终报告，并注明自建合成场景。

量化结果填法：

> 在固定的 **[N] 条自建合成测试请求**上，使用 **[具体模型和日期]**，请求分类正确 **[a/N]**，完整参数匹配 **[b/N]**；执行的 **[K] 个方案**通过独立约束检查 **[v/K]**。模型调用失败 **[e] 次**。

指标必须有分母，不能只挑一个 100%。测试集很小，不应据此称“达到生产级可靠性”。如果一条请求语义解析错了，但求解后的数学约束可行，它仍然是失败的决策请求。

不要写：

- “在 ABB 上线，实际降本 XX%”——没有企业上线和收益证据。
- “微调大模型提升性能”——本项目没有做微调。
- “所有请求 100% 安全正确”——有限回归集不能证明这一点。
- “自研优化求解器”——使用的是 SciPy/HiGHS，自己实现的是模型、约束与验证。
- “实现全自动采购”——当前只生成建议，不产生订单。

面试可先讲：

> 我关注的是如何把大模型接入可以验证的业务决策。选择补货场景，是因为它能把我的供应链和优化经验，与语言解析、服务开发和评测结合起来。我用合成数据验证工作流，模型负责提出结构化参数，优化器计算方案，独立程序检查结果。最大的限制是语言理解仍可能出错，当前也只建模单期确定性需求。
