# 单周期补货整数模型

这是用于面试作品与方法验证的简化模型。金额单位为人民币，数量为整数件。示例数据为合成数据，不代表 ABB 或其他企业的实际运营效果。

## 假设及边界

- 单仓、单计划期，每种 SKU 一个固定供应商；需求为输入的确定值。
- 期内到货视为可用于满足本期需求，未建模日内需求、交期到货前的缺货、预测误差或随机交期。
- 交期超过计划期的订单不被允许；不研究跨期在途库存或提前采购。
- 禁采限制约束新增采购，已有库存仍可使用。
- `critical` 仅为元数据。只有用户显式指定 `protected_skus` 才要求该 SKU 零缺货。
- 相对预算变化以原场景预算为基数，一次请求作用于场景副本，不累计改变其他请求。
- 服务水平为**每个 SKU 的本期数量满足率**，不是概率服务水平，也不是全局平均。

## 变量与目标

对 SKU $i$ 定义整数订货量 $q_i\ge0$、订货开关 $y_i\in\{0,1\}$、期末库存 $e_i\ge0$、缺货量 $s_i\ge0$，以及区分余量/缺货的二元变量 $z_i$。

已知初始库存 $I_i$、需求 $D_i$、单位采购成本 $c_i$、单位期末持有成本 $h_i$、单位缺货罚金 $p_i$，最小/最大订货量 $L_i,U_i$，总预算 $B$。最小化：

$$\min\sum_i(c_iq_i+h_ie_i+p_is_i).$$

采购预算仅包括采购成本；总目标额可以超过采购预算，因为还包括持有与缺货成本。缺货罚金为情景输入的建模假设，不是真实财务损失的估计。

## 约束

$$I_i+q_i+s_i-e_i=D_i,$$
$$L_i y_i\le q_i\le U_i y_i,$$
$$\sum_i c_i q_i\le B.$$

禁采 SKU 或交期超过计划期的 SKU 追加 $q_i=0$。MOQ 为零时，订货量仍为整数；二元变量允许任意状态但不影响业务结果。MOQ 大于最大订货量时，允许不下单；若服务约束强制采购，则问题不可行。

服务水平 $\alpha$ 对各 SKU 要求：

$$D_i-s_i\ge\lceil\alpha D_i\rceil.$$

显式保护的 SKU 追加 $s_i=0$。零需求 SKU 自动满足服务约束。代码通过十进制定点计算上取整，避免 `ceil(100 * 0.14)` 的浮点边界错误。

令 $\bar e_i=\max(0,I_i+U_i^{eligible}-D_i)$，$\bar s_i=\max(0,D_i-I_i)$，增加：

$$e_i\le\bar e_i z_i,\quad s_i\le\bar s_i(1-z_i).$$

这保证即使拿到的是超时可行解，也不会出现同一物料同时有库存和缺货的非物理结果。所有五类变量均标记为整数，二元变量的界为 $[0,1]$。

## 求解状态及可信边界

通过 SciPy `milp` 调用开源 HiGHS，不依赖商用求解器许可证。相对 MIP gap 目标设为零；受浮点容差和给定模型的边界约束，`optimal` 表示求解器对当前模型的最优性结论，不代表实际供应链全局最优。

| HiGHS/SciPy 状态 | 对外状态 | 处理 |
| --- | --- | --- |
| 0 | `optimal` | 必须有数值正确、整数且独立验证通过的解 |
| 1，有通过验证的 incumbent | `feasible` | 明确说明时间/迭代上限，尚未证最优，报告可用 gap 和下界 |
| 1，无 incumbent | `error` | 未找到可行解，**不能推断不可行** |
| 2 | `infeasible` | 不自动修改硬约束；返回可证明的矛盾说明 |
| 3、4、异常或验证失败 | `error` | 不提供可用于决策的订单 |

不可行诊断检查：强制需求补货遇禁采/超期、MOQ 或需求量超过订货上限、满足硬服务水平的最低必要采购成本超预算。它们是充分矛盾证据，但不是最小不可行子集（IIS）或最小放松建议。未定位矛盾时如实说明。

## 独立验证与测试

验证器不读取求解矩阵，也不相信输出中自报的成本。它直接根据原始场景和请求复算：SKU 完整性/唯一性、原始字段、整数与非负、MOQ/最大订单、交期/禁采、库存平衡、物理余量/缺货、显式保护、逐 SKU 服务水平、逐项成本和总采购预算。

测试包括小规模穷举 oracle 与 MILP 最优目标对比，MOQ/预算/交期/服务边界，库存超过需求、零需求、需求更新，以及故意篡改成本、库存、缺货、重复/缺失订单。用受控模拟覆盖超时有解、超时无解、非整数和错误求解状态，避免依赖机器速度来触发超时。

参考：[SciPy 官方 `milp` 文档](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.milp.html)。
