# 从“能运行”到“能面试”

## 先知道自己交付了什么

项目是单仓、单期补货决策的受控 Agent。LLM 把人的要求转换成允许的结构化参数；HiGHS 求解带 MOQ、预算、交期与服务要求的 MILP；独立验证器检查结果；解释直接来自经过校验的数字。

项目使用合成数据，暂无真实企业部署，未做模型微调，也没有证据表明它提升了真实采购绩效。它的价值在于展示业务建模、模型应用、工程实现和评测的方法。

## 3 分钟演示

1. 展示场景：库存、需求、MOQ、预算、交期；明确单位。
2. 输入“预算减少20%，生成补货方案”。展示提取参数、采购方案、缺货与成本。
3. 输入“全部物料不能缺货”。解释控制器 10 天到货与 7 天窗口的矛盾，以及其他可能冲突。
4. 输入“计划周期延长到14天，全部物料不能缺货”。如果预算仍不足，应继续报告不可行，不能为了完成演示偷偷加预算。
5. 打开该次审计记录，指出解析、求解、验证阶段及运行模式。
6. 展示真实模型留出评测报告，包括失败项；不把 rules 结果说成 LLM 结果。

## 必须能解释的 12 个问题

| 问题 | 合格回答应包含 |
|---|---|
| 为什么用 LLM？ | 自然语言输入、缺失条件澄清；结构化输入更稳定，LLM 不是求解必需品。需要比较交互收益与错误成本。 |
| 为什么不用模型直接报采购数量？ | 数学约束与可行性应可检查，语言生成不能提供优化最优性证明。 |
| 为什么这是 MILP？ | 数量整数、MOQ 对应是否下单二元变量、逻辑约束与线性成本。 |
| MOQ 如何建模？ | q≤Uy、q≥MOQ·y，y∈{0,1}；0是允许选项。 |
| 缺货罚金与预算有什么区别？ | 罚金参与目标权衡，预算只约束实际采购支出。 |
| 交期怎么处理？ | 超出窗口的采购在本期不可用，禁止本期下单；这是单期简化，非逐日动态库存。 |
| 如何证明正确？ | 手工可核的小实例、穷举oracle、独立验证，且验证器不复用求解矩阵。 |
| 怎么确认最优？ | 求解状态、界与gap；超时有incumbent仅说明有可行解，无incumbent不能推出不可行。 |
| Schema 正确就代表需求理解正确吗？ | 不代表。预算单位、否定、物料指代都可能错，需要语义评测及明确展示解析参数。 |
| 为什么不先做 RAG / 多智能体？ | 当前结构化场景没有大规模文档检索需求；按问题需要选组件。 |
| 模型接口失败怎么办？ | 有限重试、明确报错、不悄悄使用规则冒充模型、保留运行模式。 |
| 上线还缺什么？ | 用户身份、授权审批、数据治理、人工复核、实际业务评测、监控与容量验证；当前不自动下单。 |

## 10 天掌握路线

以下是学习安排，不是拿 offer 的保证。

| 天数 | 必须亲手完成的事情 |
|---|---|
| 第 1 天 | 独立安装、跑演示、解释每个数字和数据来源。 |
| 第 2 天 | 在纸上写出三种物料的变量、目标与约束；手算一个两物料例子。 |
| 第 3 天 | 修改一个物料的 MOQ，预测解如何变化，运行验证。 |
| 第 4 天 | 阅读验证器，亲手构造一个预算超额的坏解，让测试抓到。 |
| 第 5 天 | 阅读模型请求和结构校验，解释 JSON 合法与语义正确的区别。 |
| 第 6 天 | 增加开发集中的一种失败类型，记录修复前后结果。不要拿留出集反复调参。 |
| 第 7 天 | 通过 API 发起一次真实模型请求，找到相应审计记录。 |
| 第 8 天 | 独立实现一项小扩展，例如禁止采购物料的输入提示或更清楚的服务水平说明。 |
| 第 9 天 | 复跑评测，写出至少两个仍未解决的问题和可能方案。 |
| 第 10 天 | 录制 3 分钟演示并完成 30 分钟模拟技术面试。 |

## 下一阶段可研究的方向

只有理解了当前实现再考虑：多期库存与滚动计划、需求预测误差的稳健性、两阶段确认后应用解析参数、不可行约束集合诊断、RAG 检索有出处的采购规则。每次选择一个问题，先定义对照和评价方法，再增加模块。

## 自己完成贡献的记录

建立一份开发日志，写清“我定位的失败—修改的模块—新增验证—前后结果”。这比背诵架构更能证明能力。AI 辅助生成与自己独立设计的内容应如实区分。
